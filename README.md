# VERA — Verified Experience & Review Analyzer

VERA replaces inflated star ratings with a **calibrated experience score** for earbud reviews.
Seven signal agents read a review, an XGBoost ensemble fuses their signals, split-conformal
prediction adds a 90% interval, and Empirical Bayes shrinkage ranks products fairly.

- **Specification:** [PRD.md](PRD.md) (v1.2 corrections in §23)
- **Why things are built this way:** [DECISIONS.md](DECISIONS.md)
- **Current status / next steps:** [PROGRESS.md](PROGRESS.md), [HANDOFF.md](HANDOFF.md)

```
backend/     FastAPI API, Celery worker, ML pipeline (production — no torch)
training/    vera_training: data, labeling, fine-tuning, fusion, calibration, evaluation
notebooks/   01–08 thin notebooks generated by notebooks/build_notebooks.py
frontend/    Next.js 16 app (analyzer, product rankings, product detail, methodology)
data/        local raw / processed / labels / models (never commit local data or model artifacts)
```

## Prerequisites
| Tool | Version |
|---|---|
| Python | **3.12** (not 3.13+: pinned wheels do not exist) |
| Node.js | 22 LTS |
| uv (recommended) | any recent |
| Docker | optional — only for local Postgres/Redis |

Accounts: Supabase, Upstash, HuggingFace, Groq (current labeling runs), Render, Vercel, Colab.
Google AI Studio is needed only for the legacy Gemini provider in Notebook 02.

## Setup
```powershell
# 1. Python environment
uv venv .venv --python 3.12
uv pip install --python .venv -r backend/requirements.txt -r backend/requirements-lint.txt -r backend/requirements-test.txt
# (full notebook/fine-tuning stack: -r requirements-dev.txt --extra-index-url https://download.pytorch.org/whl/cpu)

# 2. Configuration
copy .env.example .env      # then fill in values — never commit .env

# 3. Database schema
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
cd ..

# 4. Frontend
cd frontend
npm ci
copy .env.example .env.local
```

### Infrastructure options
- **Default:** Supabase Postgres (use the *Session pooler* connection string) + Upstash Redis (`rediss://`).
- **Local alternative:** `docker compose up -d`, then
  `DATABASE_URL=postgresql://vera:vera@localhost:5432/vera` and `REDIS_URL=redis://localhost:6379/0`.

## Running locally
```powershell
# API  (http://localhost:8000/docs)
cd backend; ..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# Worker — exits immediately until all model artifacts exist (see "Models")
cd backend; ..\.venv\Scripts\celery.exe -A app.worker.celery_app worker --loglevel=info

# Frontend (http://localhost:3000)
cd frontend; npm run dev
```

## Models
The worker needs eight artifacts in `MODEL_DIR` (default `data/models/`), downloaded from
`HF_MODEL_REPO` at startup if missing. Check with:
```powershell
cd backend; ..\.venv\Scripts\python.exe -m app.ml.models.loader --check
```
They are produced by the notebooks, in order:

| Notebook | Where | Produces |
|---|---|---|
| 01 data exploration | local | cleaned earbud corpus, 2,000-review labeling pool |
| 02 label generation | local (legacy Gemini notebook; current runs use Groq scripts) | LLM labels (resumable) |
| 03 agreement analysis | local + Claude reference annotations (LLM, not human) | G1 diagnostic, `labels_v1.jsonl`; not human validation |
| 04 fine-tune + export | **Colab GPU** | experience/ABSA ONNX + tokenizers, out-of-fold scores |
| 05 train fusion | local | domain model, fusion ensemble |
| 06 calibration | local | `conformal_qhat.json`, HF Hub upload |
| 07 ablation study | local | 15-fold CV comparison, ablation table |
| 08 evaluation report | local | gates G3/G4, per-aspect metrics |

Regenerate notebooks after editing their source: `.venv\Scripts\python.exe notebooks\build_notebooks.py`.

## API
| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/reviews` | Submit a review → `202 {review_id, task_id}` |
| `GET` | `/api/reviews/{id}` | Full result (score, interval, aspects, flags, explanation) |
| `GET` | `/api/reviews/{id}/status` | Lightweight polling |
| `GET` | `/api/products` | Rankings (`sort_by`, `order`, `limit`, `offset`; `X-Total-Count`) |
| `GET` | `/api/products/{asin}` | Product aggregate + paginated reviews |
| `GET` | `/health` | Always 200; database + artifact diagnostics |

## Deployment
- No deployment resources have been created. Get explicit approval for a target before creating
  accounts, services, databases, queues, or deploy hooks.
- The production worker uses FP32 model artifacts and needs at least 2 GiB as a starting allocation;
  verify peak RSS with the complete artifact set. Render's 512 MB free tier is not suitable. The
  current `render.yaml` is not a verified production deployment configuration.
- Once a target is approved, configure the frontend at `frontend/` with server-side `API_URL` set to
  that backend's URL.
- **CI/CD:** `.github/workflows/ci.yml` on PRs; `deploy.yml` on `main` (needs `RENDER_DEPLOY_HOOK_URL`,
  `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` secrets).
- **Keep-alive:** UptimeRobot → `GET /health` every 5 minutes.
